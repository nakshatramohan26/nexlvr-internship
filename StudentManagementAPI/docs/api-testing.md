# API Testing and Demonstration Guide

> **Expected vs actual.** Everything under "Expected" below is what the code is designed to return. It has **not** been observed from a running server by the author of this guide. Run the steps yourself and take your own screenshots; your real output is the actual result.
> All names and emails are **sample data**.

## 0. Start the application

Open the project folder in VS Code (`File > Open Folder...`), open a terminal (``Ctrl+` ``) and confirm the files exist:

```powershell
Get-ChildItem pom.xml, mvnw.cmd, .mvn\wrapper
java -version      # must be 17 or newer
```

Run:

```powershell
.\mvnw.cmd spring-boot:run
```

The first run downloads dependencies (needs internet, may take a few minutes). **Expected:** the log ends with lines similar to `Tomcat started on port 8080` and `Started StudentManagementApiApplication in ... seconds`. Leave this terminal running.

## 1. Open Swagger UI

Browser: <http://localhost:8080/swagger-ui/index.html>
**Expected:** a page titled "Student Management API" with a **Students** section listing five operations: `POST /api/students`, `GET /api/students`, `GET /api/students/{id}`, `PUT /api/students/{id}`, `DELETE /api/students/{id}`.
Raw OpenAPI JSON: <http://localhost:8080/v3/api-docs>

How to use any operation in Swagger: click it, click **Try it out**, fill in the fields, click **Execute**, then read the **Server response** section (status code and body).

## 2. POST: create a student  -> expected `201 Created`

Open `POST /api/students` > Try it out. Replace the body with this **sample data**:

```json
{"name":"Nakshatra M","email":"nakshatra@example.com","department":"Information Technology","year":2}
```

**Expected:** status `201`, a `Location` response header ending in `/api/students/1`, and a body like:

```json
{"id":1,"name":"Nakshatra M","email":"nakshatra@example.com","department":"Information Technology","year":2}
```

The id is generated by the server (1 for the first student after startup).

## 3. GET all students -> expected `200 OK`

`GET /api/students` > Execute. **Expected:** a JSON array with the student(s), ordered by id. Before creating anything it is `[]` (still `200`).

## 4. GET one student -> expected `200 OK`

`GET /api/students/{id}` with `id = 1`. **Expected:** the single student object.

## 5. PUT: update -> expected `200 OK`

`PUT /api/students/{id}` with `id = 1` and this **sample data**:

```json
{"name":"Nakshatra M","email":"nakshatra@example.com","department":"Computer Science","year":3}
```

**Expected:** status `200` and the updated student with the same `id`. PUT replaces *all* fields, so send all four. Then repeat step 4 to confirm the change was stored.

## 6. DELETE -> expected `204 No Content`

`DELETE /api/students/{id}` with `id = 1`. **Expected:** status `204` and an empty body. Repeat step 4: now expect `404`.

## 7. Invalid input -> expected `400 Bad Request`

`POST /api/students` with:

```json
{"name":"","email":"not-an-email","department":"Information Technology","year":0}
```

**Expected:** status `400` and a body like (the `timestamp` will differ):

```json
{
  "timestamp": "2026-10-11T09:45:00.123Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "fieldErrors": {
    "name": "Name must not be blank",
    "email": "Email must be a valid email address",
    "year": "Year must be between 1 and 4"
  }
}
```

More 400 cases to try: `{}` (all fields required), `"year": 5`, a body that is not JSON, `"year": "two"`, and `GET /api/students/abc`.

## 8. Not found -> expected `404 Not Found`

`GET /api/students/{id}` with `id = 99` (an id that does not exist). **Expected:**

```json
{
  "timestamp": "2026-10-11T09:45:00.123Z",
  "status": 404,
  "error": "Not Found",
  "message": "Student with id 99 was not found"
}
```

`PUT` and `DELETE` on a missing id also return `404`.

## Status code summary

| Situation | Status |
|---|---|
| Student created | 201 Created |
| Student(s) retrieved, student updated | 200 OK |
| Student deleted | 204 No Content |
| Invalid/missing field, malformed JSON, non-numeric id | 400 Bad Request |
| Student id does not exist | 404 Not Found |

## Optional: test from PowerShell instead of Swagger

`curl` in Windows PowerShell 5.1 is an alias of `Invoke-WebRequest`, so use `curl.exe` for raw output. JSON in a file avoids PowerShell quoting problems:

```powershell
Set-Content -Path student.json -Value '{"name":"Nakshatra M","email":"nakshatra@example.com","department":"Information Technology","year":2}'
curl.exe -i -X POST http://localhost:8080/api/students -H "Content-Type: application/json" --data "@student.json"
curl.exe -i http://localhost:8080/api/students
curl.exe -i http://localhost:8080/api/students/1
curl.exe -i -X PUT http://localhost:8080/api/students/1 -H "Content-Type: application/json" --data "@student.json"
curl.exe -i -X DELETE http://localhost:8080/api/students/1
curl.exe -i http://localhost:8080/api/students/99
```

`-i` prints the status line and headers. Delete the sample file afterwards: `Remove-Item student.json`.

## Stop the application safely

Click the terminal running the app and press `Ctrl+C`. If PowerShell asks `Terminate batch job (Y/N)?` type `Y`. The in-memory students disappear; this is expected.

## Run the automated tests

```powershell
.\mvnw.cmd test
```

**Expected (not yet observed by the author):** the build ends with `Tests run: 22, Failures: 0, Errors: 0, Skipped: 0` and `BUILD SUCCESS`. If the numbers differ, trust your screen, not this document. If anything fails, copy the failing test name and the first error lines for debugging.

## Troubleshooting

| Problem | Fix |
|---|---|
| `Port 8080 was already in use` | Stop the other program (run `netstat -ano` and look for the line with `:8080`, then `taskkill /PID <pid> /F`) or set `server.port=8081` in `src/main/resources/application.properties` and use port 8081 in the URLs. |
| `The JAVA_HOME environment variable is not defined correctly` | Set `JAVA_HOME` to your JDK folder, then open a **new** terminal. |
| `release version 17 not supported` / `invalid target release` | Your JDK is older than 17. Install JDK 17 or 21. |
| Dependencies fail to download (`Could not transfer artifact`, timeouts) | Check internet/proxy/VPN, then rerun with `.\mvnw.cmd -U spring-boot:run`. If a download was cut off, delete the broken folder under `%USERPROFILE%\.m2\repository` that the error names and retry. |
| `mvnw.cmd` is not recognized | The Maven wrapper is missing; follow "Add the Maven wrapper" in the README. |
| Swagger page is blank or 404 | Use exactly `/swagger-ui/index.html` and check the app is still running. |
| Everything returns `[]` after a restart | Expected: storage is in memory only. |
